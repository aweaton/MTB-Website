# Task planning

## When to use
Convert a new or ambiguous coding request into a bounded task brief and objective acceptance criteria; use for intake, not routine execution.

## Procedure
1. Read the user request, issue and repository policy; identify intended user-observable behavior.
2. Write the goal, in-scope and out-of-scope changes, and 2–6 testable acceptance criteria.
3. Flag unknowns, permissions, compatibility, data-loss or security effects; resolve high-risk uncertainty before implementation.
4. Use templates/task-brief.md; request human agreement when a high-impact interpretation is necessary.

## Required output
Task brief with criteria, open decisions, risk and approval gates.

## Stop and escalate when
Conflicting requirements, unapproved destructive changes or missing authority.

Follow repository `AGENTS.md`; never claim unexecuted tests passed and never merge/deploy without approval.
